## 1. 产品摘要与范围

Home Chef 是长沙本地认证厨师上门服务撮合平台。用户选择经平台审核的厨师与套餐，提交需求并选择定金或全款支付；支付成功后订单进入待接单/平台派单，厨师按约上门履约，采购和增项在平台内凭证结算，服务完成确认后按规则结算给厨师。

**试运营目标：** 验证需求、形成可审计的认证—报价—支付—履约—售后闭环、降低陌生人上门交易不确定性。首批开放片区白名单为 `BLK-REGION-001`，未确认前不得对外开放。

| MVP 包含 | MVP 不包含 |
|---|---|
| 四维审核与试岗、双食材模式、3km片区、八大菜系筛选、套餐/档期、定金或全款、履约凭证、取消退款/售后、匹配/急单、IM风控、保险绑定、基础优惠券、BI与完整通知 | 履约保证金、多厨师协作、全国开城、会员/B端商家、虚拟中间号、洗碗/深度清洁/厨余清运、直播、复杂菜谱编辑器、付费自然排序 |

## 2. 术语与服务边界

| 术语 | 含义 |
|---|---|
| 预约申请 | 用户提交的待报价/待支付需求；正式接单计时在首付款成功后开始。 |
| 报价单 | 套餐或厨师提交的版本化费用明细；支付前确认并固化。 |
| 订单成立 | 所选定金或全款到账并固化报价和规则，进入待接单；自选支付时硬锁，匹配在抢单成功时绑定厨师并硬锁。 |
| 服务完成确认 | 现场确认或服务结束起默认72h自动确认，触发结算资格检查；尾款到账单独记录。 |
| 普通售后窗口 | 完成确认后7天内可申请普通售后；待完成确认时也可提出异议，不额外设置固定结算冻结期。 |
| 服务性收入/代垫 | 前者计佣，后者实报实销不计佣；正式口径见 `TR-COMMISSION-002`。 |

`PRD-SERVICE-001`：基础服务为确认菜单的备菜、烹饪、装盘、简单灶台/台面清理和餐具归位；不含餐后洗碗、厨余带走、全屋保洁。按原文第七章，洗碗、深度厨房清洁、厨余清运放入V2，不混入V1套餐。下单填写用餐人数（标记儿童/老人）、日期/上门时间段、口味、过敏源、厨房设备与入户条件；过敏源字段必须明确填写或选择无已知过敏，厨师端顶部高亮提醒。

不包含：全屋/深度清洁、非本次烹饪产生物品的清洁、厨房维修、儿童看护、医疗营养建议、未经确认的宴会布置、酒类和受限商品代购。食品安全与材料要求受 `BLK-FOOD-001` 约束。

`PRD-INGREDIENT-001`：厨师自带食材/用户自备食材双模式均纳入V1，并可委托采购部分食材。自带模式逐项列示食材成本、加工、上门及基础简易清理费用，确认食材清单并上传小票和实拍，厨师负责所供食材品质；自备模式无委托采购时不得计食材费，用户负责所供食材新鲜度，厨师发现变质可拒做并协商改期/部分退款。代办采购单独报价采购服务费，食材实报实销；责任处理仍依事故证据和适用规则。

## 3. 角色与最小权限

| 角色 | 核心目标 | 摘要权限 |
|---|---|---|
| 用户 | 找厨师并安全完成家庭用餐 | 搜索、申请、支付、取消、确认、评价、投诉 |
| 厨师 | 展示能力、接单、履约和收入 | 入驻、配置服务/档期、报价、履约、查看本人结算 |
| 片区运营 | 管理供给与活动 | 区域、活动、容量及BI；敏感材料按任务授权 |
| 风控 | 处理违规与申诉 | 聊天风险、黑名单、处罚及保险异常；资金动作走财务 |
| 审核员 | 审核厨师和内容 | 审核、补件、暂停、复审；不执行资金操作 |
| 客服/仲裁 | 处理异常和争议 | 查看必要订单证据、受理售后、提交裁定建议 |
| 财务 | 执行退款、结算、对账 | 仅执行已审批资金动作 |
| 超级管理员 | 管理角色和配置 | 高风险操作审计、不得绕过审批留痕 |

字段级访问、脱敏、审批及审计以 `COMP-RBAC-001`、`COMP-RBAC-002` 为唯一事实源。身份证、健康材料、联系方式和完整地址仅在必要条件下可访问并留痕。

## 4. 核心旅程

### 4.1 用户预约（`PRD-USER-005`）

```text
微信登录/手机号绑定 → 选择服务地址或区域 → 浏览认证厨师
→ 筛选菜系、价格、评分、档期 → 查看主页和套餐
→ 填写人数、时间、口味、过敏、厨房和食材方式 → 选择自主选厨/平台匹配
→ 确认报价并支付定金或全款（待接单；自选锁档，匹配待指派）
→ 自选厨师5min内接单，或候选厨师抢单并原子绑定档期
→ 服务前地址解锁 → 到达/开始/完成及凭证 → 最终费用确认
→ 服务结束后用户确认或72h自动确认 → 开放评价/售后，并检查结算资格
→ 尾款/最终费用结清且无争议 → 按批次结算
```

状态、金额、超时、退款和结算以 `TR-*` 为唯一规则；支付成功后订单先进入待接单，页面不得自行解释或重算金额。

### 4.2 厨师入驻（`PRD-CHEF-001`）

```text
微信登录 → 申请厨师 → 实名和资质材料 → 服务能力/价格/区域/档期/作品
→ 签署协议与承诺 → 系统初筛/人工四维审核、补件或驳回
→ 培训考试与前3笔试岗订单 → 考核合格转正式厨师
```

基础认证与健康证有效才可进入试岗接单；前三单重点监控、电话回访，试岗不合格收回接单权限，季度复审。专业认证与运营等级不暗示行政许可。人脸实名、一人一号按增强版需求接入，实际渠道和必要数据处理由合规文档落实。试岗评价/投诉处理见 OPS-CHEF-003。

### 4.3 履约、费用与售后（`PRD-FULFILL-001`）

已接单厨师在服务前24h取得本订单完整地址；急单处于24h内时，接单成功即满足时间条件。更早解锁须用户授权；未抢到订单的候选不可获取完整地址。出发/到达/开始/完成均留时间和凭证，完成上传成品菜照片。服务结束起默认72h自动确认，用户可现场确认或提出争议；单纯未付尾款不重置确认时钟，但阻断结算。确认起7天内可初评、15天内可追评。

## 5. 领域模型与档期

| 领域对象 | 关系 |
|---|---|
| 用户/地址 | 用户可管理地址；订单保存最小必要的地址快照。 |
| 厨师/认证/服务/档期 | 认证有效的厨师发布服务与可预约档期。 |
| 预约/报价/订单 | 支付前确认报价，首付款后待接单；候选、正式绑定厨师、接单时限与档期分别记录。 |
| 订单/支付/履约/费用/售后/结算/评价 | 七个状态域独立维护，见 `TR-*`。 |

`PRD-SCHEDULE-001`：普通预约沿用最短提前24h、最远30天、报价有效30min、服务前后60min缓冲的补充默认值，允许版本化调整。急单为2h内需上门，不套用24h限制，最小提前量按实际可履约范围配置。原文建议上门时段以30min为粒度，须另记服务持续时长以校验档期。自选接单默认5min，匹配流拍N分钟待发布；所有路径须校验认证、区域、档期与缓冲，同一厨师不能有冲突硬锁。

## 7. 地址、消息、评价与推荐

`PRD-PRIVACY-001`：下单前展示区域及近似距离；首付款成功、本人已接单且到服务前24h时，才对本单厨师解锁地址；用户可主动提前授权。未接单候选、已取消或结束订单不常驻展示完整地址。站内与订阅消息覆盖新订单、接单/拒单、流拍、出发/到达、改约、余款、完成、退款、售后、健康证、处罚、复审、保险和结算；详情见 OPS-NOTIFY-001。

`PRD-IM-001`：用户与厨师使用小程序内 IM；禁止跳转微信。微信、手机号、QQ、线下转账等敏感词拦截并记录风控事件；聊天记录云端留存，改约和报价确认使用结构化卡片。

`PRD-REGION-001`：片区按城市、行政区和住宅小区管理，支持地图边界、启停、厨师多片区接单开关和容量/候补队列。默认服务半径 3km 直线距离；未开通区域可预约开通提醒；超出范围的搜索结果标注距离，不能默认下单。

`PRD-MATCH-001`：用户可自主指定厨师或选择平台匹配。匹配模式按菜系、距离、评价和档期向最多 3 位厨师推送；N 分钟无人接单则流拍并退回已付款，急单优先推送 1km 内空闲厨师。

`PRD-INSURANCE-001`：V1每笔上门订单自动关联平台服务责任险（人身意外、财产损失），提供保单状态/查询与出险报案；取消订单终止对应保险并记录渠道结果。拒保或投保失败转异常处理，不能显示已投保或允许无保障履约。产品、覆盖、赔付及退保机制由 BLK-FOOD-001 验证，不将“接口待接通”当作取消V1需求。

`PRD-REVIEW-001`：完成确认起7天初评、15天追评；支持口味/服务态度/准时度分项、文字与图/视频、匿名、内容举报与申诉。取消/爽约不生成普通评分；争议评价可延迟公开，内容违规和履约责任分别处理。榜单在认证、区域、档期、开关、处罚等硬条件后，按好评35%、履约/投诉25%、复购/真实单量20%、等级/试岗15%、近7天活跃5%的默认权重排序（后台可调）；片区热门/金牌/新人榜，新人前10单扶持，疑似刷评剔除排名并记录风控。普通差评按治理流程处理；试岗另按 OPS-CHEF-003 考核。

`PRD-COUPON-001`：V1支持新人、满减、片区、节日家宴基础券及售后补偿券；展示门槛、适用片区、有效期和叠加限制，领券/核销/退款退券均留版本。具体额度、分摊及券后定金基数见 TR-COUPON-001、对齐记录 DTL-COUPON-001。
