# Home Chef 长沙上门私厨小程序

**需求规格说明书（PRD）**  
版本：v0.1（需求梳理稿）  
日期：2026-09-07  
适用阶段：长沙试运营 / MVP

> 本文是产品和业务讨论基线，不构成法律意见。食品经营资质、健康证明、平台责任、支付分账、保证金和个人信息处理方式，在上线前须由专业法律顾问、支付机构及属地监管要求复核。

## 1. 产品概述

### 1.1 产品定位

Home Chef 是面向长沙本地的认证厨师上门服务撮合平台。用户按照位置、菜系、价格、评价和档期选择厨师，在平台内沟通、预约并全额预付；厨师确认订单后上门完成做饭及可选增值服务，平台在履约完成和售后保护期后结算。

### 1.2 试运营假设

- 首期城市：长沙；由运营后台配置开放的行政区/商圈/片区。
- 供给：每个开放片区先招募 1～2 名私厨、餐厅厨师或兼职厨师。
- 服务：做饭为基础服务；买菜、备菜、餐后清洁、交通和加时为可选项目。
- 交易：厨师确认后用户一次性支付订单全额，所有改价、采购和退款均在平台完成。
- 平台角色：提供信息展示、撮合、支付、履约凭证、客服和评价工具；具体食品制作及服务责任按平台协议和适用法律执行。

### 1.3 产品目标

1. 在长沙验证用户是否愿意预约认证厨师上门服务。
2. 建立可审计的厨师认证、报价、支付、履约和售后闭环。
3. 用透明的服务信息和评价机制降低陌生人上门交易的不确定性。
4. 通过接单效率、履约质量和投诉率改善厨师推荐，而不是单纯按付费排名。

### 1.4 MVP 不包含

- 复杂的即时派单和自动调度。
- 多厨师协作、全国开城和复杂会员体系。
- 菜谱社区、直播、内容裂变等非交易核心功能。
- 发票能力（需求暂不考虑，后续按主体和税务方案补充）。
- 复杂的在线定制菜谱编辑器；定制需求先用订单备注和厨师独立报价完成。

## 2. 用户角色与权限

| 角色 | 主要目标 | 核心权限 |
|---|---|---|
| 普通用户 | 找到合适厨师并安全完成一次家庭用餐 | 搜索、查看、沟通、预约、支付、取消、确认、评价、投诉 |
| 厨师 | 展示能力、获得订单并完成服务 | 入驻认证、编辑主页、设置服务/价格/档期、报价、接单、履约、查看结算 |
| 运营审核员 | 确认厨师和内容符合规则 | 审核资料、处理补充/驳回、审核内容、冻结厨师 |
| 客服/仲裁员 | 处理支付、取消和履约争议 | 查看订单和聊天、发起退款/补款、记录仲裁结果 |
| 财务管理员 | 管理抽佣和结算 | 配置佣金、查看账单、发起结算和对账 |
| 超级管理员 | 管理系统配置和权限 | 角色授权、区域/规则/标签配置、审计日志 |

权限原则：最小权限、按岗位分权；身份证、健康证明、联系方式和完整地址仅在必要环节可见并记录访问日志。

## 3. 核心业务流程

### 3.1 用户预约流程

```text
微信登录/手机号绑定
  → 选择位置或服务地址
  → 浏览附近认证厨师
  → 按菜系、价格、评分、距离、档期筛选
  → 查看厨师主页与套餐
  → 选择服务项目、时间、人数、食材方式
  → 平台内沟通（可选）
  → 提交预约申请
  → 厨师确认并提交/确认报价
  → 用户在支付时限内全额付款
  → 服务前提醒与地址解锁
  → 到达签到、开始服务、上传凭证
  → 完成服务，确认实际采购/加时费用
  → 用户确认完成（或超时自动完成）
  → 售后保护期结束后平台结算
  → 用户评价/投诉
```

### 3.2 厨师入驻流程

```text
微信登录
  → 申请成为厨师
  → 实名和资质材料提交
  → 服务能力、价格、区域、档期和作品填写
  → 签署平台协议与食品安全承诺
  → 平台初审/必要时人工核验
  → 通过、补充材料或驳回
  → 发布主页并可接单
```

### 3.3 订单状态

正常状态：

```text
待厨师确认 → 待用户支付 → 已支付待服务 → 服务中
→ 待确认费用/完成 → 售后保护期 → 已结算 → 待评价/已评价
```

异常状态：厨师拒绝、确认超时、支付超时、用户取消、厨师爽约、退款中、改价待确认、售后处理中、争议关闭。

所有状态转换必须记录操作者、时间、前后金额、原因和关联凭证；客户端展示用户可理解的状态文案。

## 4. 厨师认证标准

### 4.1 认证分层

| 层级 | 含义 | 可接订单 |
|---|---|---|
| 资料未完成 | 尚未提交完整材料 | 不可 |
| 待审核 | 已提交，平台审核中 | 不可 |
| 基础认证 | 实名、身份和健康材料通过，协议已签署 | 可接基础服务订单 |
| 专业认证 | 基础认证 + 厨师证/职业经历/试做或视频核验通过 | 可展示专业认证标识 |
| 金牌/优选（运营标签） | 专业认证基础上的履约和口碑等级 | 可获得推荐加权，不代表政府资质 |

“金牌”“优选”是平台运营等级，不得暗示行政许可或官方背书；展示时同时显示认证通过日期和有效期。

### 4.2 必填材料

**身份与联系**

- 真实姓名、证件类型和证件照片（后台审核，不向用户公开）。
- 手机号、紧急联系人（按必要性收集）。
- 人脸/活体核验或人工视频核验（是否启用由合规评估决定）。

**专业与健康**

- 厨师证书、职业技能等级证书、培训证书或可验证的从业经历（至少提供一种；材料类型由运营配置）。
- 有效健康证明/从业人员健康检查相关材料；记录签发日期、有效期和核验结果。
- 擅长菜系、特色菜、服务年限、过敏原和饮食限制处理能力自述。

**服务与履约**

- 服务区域、服务半径、可预约时段和最短提前预约时间。
- 基础服务费、套餐/按人数/按小时价格，以及买菜、备菜、清洁、交通、加时规则。
- 菜品照片、短视频或作品集（必须获得上传者授权，不得盗用）。
- 平台服务协议、隐私政策、食品安全责任承诺和取消/违约规则确认。

**可选增强材料**

- 推荐人或历史任职证明。
- 食品安全培训记录、保险信息。
- 线下试做、视频面试或运营人员回访记录。

### 4.3 审核规则

- 材料完整性：必填项齐全、图片清晰、证件未过期。
- 一致性：实名信息、证件、收款主体与平台账户一致；不一致进入人工复核。
- 有效期：健康证明和其他时效材料到期前 30/7 天提醒，到期自动暂停接单，重新审核后恢复。
- 内容安全：作品不得含违法、侵权、虚假宣传、联系方式引流或无法证明的“官方认证”表述。
- 风险复核：投诉、食品安全事故、身份异常或多次爽约触发重新审核。
- 审核结果：通过、补充材料、驳回、暂停、永久禁入；每次必须填写原因和审核员。

### 4.4 认证展示

用户端只展示：认证状态、认证类型、有效期/最近复核时间、擅长菜系、服务数据和作品。身份证号、证件照片、住址、私人手机号不展示。

## 8. 评价规则

### 8.1 评价资格和时限

- 只有已完成且已结算/进入售后保护期的订单可评价。
- 每个订单用户评价一次；厨师可对用户评价一次，双方互不可见直到双方完成评价或评价期结束。
- 评价期建议为服务完成后 7 天，逾期不可新增公开评价但仍可投诉。
- 取消、爽约和争议订单不生成普通服务评分，进入单独的履约记录。

### 8.2 评分维度

用户评价厨师（1～5 分）：

- 菜品口味
- 服务态度与沟通
- 准时与履约
- 卫生与操作规范
- 价格与描述一致性

用户可选标签：味道好、食材新鲜、准时、沟通顺畅、收拾干净、适合家庭、性价比高；负向标签：迟到、临时改价、卫生问题、与描述不符、沟通不畅、临时取消。

厨师评价用户（内部为主）：

- 需求描述准确
- 地址/时间配合
- 沟通礼貌
- 付款及时
- 临时变更情况

### 8.3 评分计算

- 展示“综合评分”和各维度分数，保留一位小数。
- 新厨师订单数较少时显示“暂无足够评价”，不显示虚假的高分。
- 推荐使用贝叶斯/最小样本修正，避免一单 5 分就超过长期稳定服务者。
- 评分只使用真实完成订单；疑似刷单、利益交换、辱骂、隐私泄露和与服务无关内容可隐藏并记录原因。
- 平台不得因用户给出真实差评而直接处罚用户；恶意评价需提供证据并允许申诉。

### 8.4 评价治理

- 用户可举报评价，后台支持通过、隐藏、恢复和申诉。
- 聊天、订单凭证、签到和小票可作为争议证据。
- 评价内容不得公开身份证、手机号、住址、微信号等个人信息。
- 商家/厨师不得以返现、赠品强迫好评；如开展激励，必须对所有符合条件的评价一视同仁并标注。

## 9. 积分、等级与推荐规则

### 9.1 厨师信用分

建议初始 100 分，后台配置上下限和事件分值。积分是平台信用指标，不是现金，也不替代法律责任。

| 事件 | 建议分值 | 说明 |
|---|---:|---|
| 认证通过 | +5 | 一次性 |
| 完成订单 | +1 | 可设置月度上限 |
| 用户有效好评（4～5 分） | +1 | 防止刷分，按月封顶 |
| 用户投诉经核实成立 | -5～-20 | 按严重程度 |
| 无正当理由临时爽约 | -20～-40 | 同时按保证金规则处理 |
| 无故迟到/提前离场 | -5～-15 | 以签到和订单证据为准 |
| 未经确认改价或线下引流 | -20～-50 | 严重时暂停/清退 |
| 健康证明过期未更新 | -10 | 并自动暂停接单 |
| 主动完成平台培训/复审 | +2 | 每周期有限次 |

扣分前应通知厨师并提供申诉入口；食品安全、骚扰、欺诈等重大事件可先暂停接单再调查。

### 9.2 等级建议

等级仅用于推荐和权益，不改变基础安全审核：

- 新入驻：完成认证，订单少于 10 单。
- 认证厨师：认证通过且信用分达到配置阈值。
- 优选厨师：近 90 天订单数、评分、取消率、投诉率同时达标。
- 金牌厨师：更高订单数和稳定履约门槛，需运营复审。

示例门槛（上线前可调）：近 90 天完成 ≥30 单、有效评分 ≥4.7、厨师取消率 ≤2%、成立投诉率 ≤1%，且健康证明有效。

### 9.3 推荐排序

推荐必须优先满足硬条件：认证有效、服务区域匹配、档期可用、用户需求匹配。硬条件之后再按以下因素排序：

```text
匹配度 35% + 履约/响应 25% + 评价质量 20% + 距离 15% + 活跃度 5%
```

权重和加权范围由后台配置，并在运营报表中可解释。不得以付费提高排序替代认证和安全条件；活动位应明确标注“推广”。

## 10. 费用、支付与结算规则

### 10.1 费用

```text
订单总额 = 基础服务费 + 增值服务费 + 交通费 + 预计采购费 + 加时/增项 - 优惠
```

- 套餐价、按人数、按小时均可配置。
- 厨师报价必须提供明细和有效期。
- 用户确认报价后全额支付；支付超时释放档期。
- 预计采购费单独记录，服务后凭小票按实际金额多退少补。

### 10.2 改价

- 服务前改价：厨师提交，用户确认后重新支付/退款差额。
- 服务中或服务后：仅允许实际采购、用户主动增项和约定加时；必须提供凭证并经用户确认。
- 单次改价金额和累计改价比例可配置；超过阈值进入人工审核。

### 10.3 佣金与结算

```text
平台佣金 = 最终结算订单金额 × 厨师佣金比例
厨师应得 = 最终结算订单金额 - 平台佣金 - 已确认应扣费用
```

佣金比例可按厨师等级、区域、服务类型配置。最终采用微信支付担保交易、分账或其他方案，须在上线前完成支付机构合规确认。

## 11. 取消、爽约与保证金

### 11.1 用户取消

后台按“距服务开始时间”配置退款比例、采购费和交通费处理规则。取消确认页必须展示原金额、退款金额、扣除金额和原因。

### 11.2 厨师取消

- 用户已付金额按规则全额退回或优先保障用户权益。
- 无正当理由爽约：扣履约保证金、扣信用分、降低推荐；重复发生可暂停或清退。
- 厨师因不可抗力取消：提交说明和凭证，由客服判定是否免罚。

### 11.3 履约保证金（待财务/法务确认）

- 是否收取、金额、托管方式、扣除上限和退出退款流程由后台配置。
- 平台不得将保证金与用户支付资金混记；必须有独立账目、冻结/扣除/解冻流水。

## 12. 隐私、安全与内容治理

- 定位只在搜索附近厨师和判断服务范围时使用；允许用户手动选择区域。
- 下单前展示大致区域/距离；订单确认且满足必要条件后才解锁详细地址。
- 用户和厨师手机号默认隐藏，平台内消息为唯一沟通渠道。
- 身份证、健康证明、精确位置、聊天和支付信息按最小必要原则处理，设置访问权限、留存期限和删除/注销流程。
- 首次收集定位、身份、相册/相机、聊天图片等信息时展示用途、范围和拒绝后的替代路径；隐私政策和小程序隐私指引保持一致。
- 聊天和作品支持举报；识别二维码、微信号、手机号等线下引流信息并提示或拦截，保留人工复核。
- 服务前后照片、签到和小票仅用于履约、售后和审核，不默认公开到厨师主页。

## 13. MVP 验收指标

### 13.1 业务指标（长沙试运营）

- 入驻并通过基础认证的厨师数、各片区覆盖率。
- 用户从浏览到提交预约的转化率。
- 厨师确认率、平均首次响应时间、支付成功率。
- 完成订单数、取消率、厨师爽约率、投诉成立率。
- 订单评价率、综合评分、复购/重复预约率。
- 退款处理时长和结算对账差异率。

### 13.2 功能验收

- 未认证或材料过期厨师不能公开接单。
- 用户无法在订单成立前看到厨师私人手机号和完整地址。
- 厨师未确认前不产生支付；确认后超时未支付自动释放档期。
- 改价必须有明细、原因和用户确认，所有金额变化可审计。
- 取消时系统按后台版本化规则准确计算退款和补偿。
- 采购费支持预估支付、凭证上传、多退少补。
- 完成订单才能评价；异常评价可举报、隐藏和申诉。
- 佣金、保证金、退款和结算流水可按订单追溯。
