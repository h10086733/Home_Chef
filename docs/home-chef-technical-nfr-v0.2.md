# Home Chef 技术非功能需求规格

**版本：** v0.2（草案）  
**唯一事实源：** 性能、可用性、安全、一致性、审计、恢复与可观测性  
**关联：** [交易规则](home-chef-transaction-rules-v0.2.md)｜[合规与数据](home-chef-compliance-data-v0.2.md)｜[验收矩阵](home-chef-acceptance-matrix-v0.2.md)

本次对齐日期：2026-09-10。业务来源与待定参数见 [对齐记录](home-chef-requirements-alignment-v0.2.md)；部署、模块和一致性实现见 [技术架构基线](home-chef-architecture-v0.1.md)。

## 1. 范围与测量约定

适用于用户/厨师小程序、运营后台、订单、定金/尾款/全款、退款、补款、结算、派单、优惠券、IM、保险、消息、文件和第三方集成。所有时间使用 `Asia/Shanghai`；金额以人民币分存储计算；P95 以月度生产窗口或等效压测窗口测量。任何达不到本基线的例外必须有风险、临时措施、到期日和批准人。

## 2. 可用性与性能

| ID | 要求 | 验证 |
|---|---|---|
| `NFR-AVAIL-001` | 月度核心交易可用性 ≥99.5%，不含提前公告维护窗口。 | 监控报表、故障记录。 |
| `NFR-PERF-001` | 常规读写接口 P95 ≤1.5s；核心页面可交互 P95 ≤3s。 | APM/真机或压测证据。 |
| `NFR-PERF-002` | 订单提交、报价、支付结果查询、退款申请应提供明确处理中状态，不得因同步等待第三方而重复创建业务单。 | 场景测试。 |
| `NFR-PERF-003` | 高峰期订单推送响应<2s；报价/首付款/接单事件至推送请求获得通道响应的耗时作为内部测量口径，另记录设备送达，不将通道响应当作厨师已读。 | 声明并发量与通道条件，记录耗时分布、超2s比例和失败重试；不得用常规接口P95代替推送验证。 |
| `NFR-CAP-001` | 容量阈值、并发假设和扩容责任在上线前登记；达到 70% 预警、85% 升级。 | 容量仪表盘。 |

## 3. 交易一致性与幂等

`NFR-CONSIST-001`：创建预约、提交报价、锁档、支付确认、取消、退款、补款、服务完成、结算、评价和通知均须有业务幂等键。重复请求、重复或乱序支付回调不得重复扣款、退款、锁档、计佣或结算。

`NFR-CONSIST-002`：自选支付时硬锁；匹配抢单时原子地校验待接单、候选权限和重叠档期并唯一绑定厨师。抢单/超时、两个订单抢同一档期均不得产生矛盾成功；自选支付成功锁档失败进入异常退款，匹配抢单失败不得占用档期或读取地址。

`NFR-CONSIST-003`：金额使用整数分；每笔业务资金动作均有可追溯流水。规则快照、报价版本、费用明细、状态事件与支付渠道单号不可被覆盖修改。关键操作采用事务、可靠事件或可重试补偿，避免“已扣款未建单”“已退款未记账”。

`NFR-CONSIST-004`：尾款/增项各有支付单和幂等键；退款逐笔关联原支付且不超过净实收。重复/乱序回调不抹掉已收定金、不复活取消订单。领券、锁券、核销、退券、保单创建/取消、报案和消息按事件幂等处理，结算资格与资金指令原子校验；在途结算先查询渠道再处理售后。

## 4. 安全、授权与隐私

| ID | 要求 |
|---|---|
| `NFR-SEC-001` | 传输使用安全协议；敏感数据静态加密、密钥隔离与轮换；不得在普通日志写入完整身份证、地址、手机号、支付回调原文。 |
| `NFR-SEC-002` | 服务端强制执行 `COMP-RBAC-001`、`COMP-RBAC-002`；不得只依赖前端隐藏。后台高风险操作要求重新认证或双人复核。 |
| `NFR-SEC-003` | 文件上传限制类型/大小，进行恶意文件扫描；下载、导出和查看敏感材料留审计且可追责。 |
| `NFR-SEC-004` | 登录、支付、地址、聊天、导出和后台接口须具备鉴权、越权防护、限流与异常访问告警。 |

## 5. 审计、监控与告警

`NFR-AUDIT-001`：金额、订单状态、地址解锁、敏感材料访问、退款/补款/结算、权限、规则配置、数据导出操作 100% 记录审计事件，包含主体、目标、时间、来源、结果、前后值、原因和关联订单/工单。审计日志不可由普通业务角色删除。

`NFR-OBS-001`：监控支付/退款/补款失败或超时、订单状态卡死、锁档冲突、结算差异、材料到期停单失败、消息失败、第三方不可用、异常权限访问及 P0/P1 事故。P0/P1 技术故障应在 5min 内告警至值班人员；告警必须关联运行手册。

## 6. 恢复、第三方与发布

| ID | 要求 | 基线 |
|---|---|---|
| `NFR-DR-001` | 关键交易数据备份与恢复演练。 | RPO ≤15min；RTO ≤4h。 |
| `NFR-3P-001` | 支付、地图、IM/消息、保险、存储不可用时采用重试、状态查询、补偿任务、人工接管和用户可理解文案。 | 不可静默丢单、越过敏感词拦截或将失败投保显示为已承保。 |
| `NFR-REL-001` | 配置、规则、发布可追溯并支持回滚；金额/取消规则有生效时间与订单快照。 | 历史订单不重算。 |
| `NFR-COMPAT-001` | 微信小程序基础库 **≥ 3.0.0**；iOS **14 及以上**、Android **10 及以上**；弱网下订单、上传和消息可恢复。 | 上线前在最低支持版本及主流机型真机覆盖。 |

## 7. 验证与例外

每项 NFR 需在 `AC-NFR-*` 中有测量方法、环境、阈值和证据。支付回调重复/乱序、断网重试、锁档并发、第三方失败、备份恢复、越权和日志脱敏是 P0 验收。若某项不能满足，负责人须提交风险评估、人工兜底、修复期限和批准记录；未批准的 P0 例外阻断上线。
