## 1. 现在已经实现的

这些是代码里的路径，不是需求文档里的目标。正式部署、真实 AppID、微信支付和真机验收都还没完成。

| 能力 | 实际行为 |
|---|---|
| 账号 | 密码注册登录；微信手机号登录并绑定旧账号。手机号加密。角色有用户、厨师、运营、审核、客服、财务、财务负责人、风控、超管。网页按角色显示菜单。没有验证码，没有独立后台账号，没有登录 IP 日志 |
| 发现与地址 | 公开厨师列表，按菜系、价格、距离筛选，可收藏。地图选点已接。服务范围仍是坐标半径加片区代码，没有小区多边形。未开通片区不能下单 |
| 预约 | 自选厨师报价。定金或全款由服务端计算。待支付订单不锁厨师。支付成功后才邀请接单。自选厨师超时取消并退已付款。档期互斥。采购增量必须用户确认且到账后才改预算 |
| 履约 | 出发、到达、服务中、完成。完成要成品照片；有采购费时要小票。新订单服务结束后 48 小时自动确认，旧订单仍按快照 72 小时。确认后 7 天可评价，可追评。支持改约，双方确认才生效 |
| 收款与退款 | 微信收款、查单、验签、原路退款。退款是客服建议、负责人审批、财务执行，金额由服务端按规则算。客户端不能直接把订单改成已到账 |
| 厨师收入 | 新订单在评价完成或 7 天评价期结束后结算；旧订单继续按至少 168 小时保护期。费用结清且没有开放售后才允许结算。新提现由一人审核、另一人登记线下打款凭证；历史微信转账继续查单。微信直接分账保持不变 |
| 厨师审核 | 上传材料、人工通过或驳回、驳回原因通知厨师、试岗状态、厨师自建套餐和档期。健康证到期后，定时任务会关掉接单并标为暂停。没有到期前 30 天提醒，没有 OCR、活体、季度复审和培训考试 |
| 售后与聊天 | 订单内售后和事故工单。客服或风控要有开放工单才能看聊天，并留下查阅记录。敏感词拦截联系方式和线下转账。员工不能代发消息 |
| 营销与协议 | 规则打开后可领一张新人服务费券，只抵服务费。没有菜价券、团购、积分、次卡、用户余额。协议没有在线版本 |
| 后台页面 | 工作概览、订单、厨师审核、售后工单、资金流水、结算提现、财务授权、规则 JSON。概览只有订单数、厨师数、开放工单、累计实收和退款。没有用户冻结、厨师封禁台账、协议编辑、会话检索和导出报表 |
| 保险 | 业务模式不创建保单。沙箱里的报案不能当成已投保 |

## 4. 重新整理后的本轮需求

下面是这一轮要对齐的需求。旧订单、已经进入微信转账的提现单，不改原来的规则。

1. 小程序发布检查继续核对真实 AppID 和正式 API 地址。没有这两项，就不能算真机可验收。
2. 新订单在服务结束进入待确认时记下 48 小时。没有这份记录的旧单仍按 72 小时自动确认。
3. 新确认的订单，在用户提交评价之后，或 7 天评价窗结束仍未评价之后，才可以结算。默认不再额外等待。欠款、费用未结清、开放售后仍然不能结算。已经确认、并按 168 小时保护期走的订单，继续用 168 小时。
4. 新的提现申请冻结余额。财务核对收款户名，不能审自己的单。另一名财务人员登记线下打款凭证后，才记为已打款。没有凭证不能标成功，这一步不调用微信转账。驳回或取消会释放冻结。已经在微信转账流程里的单，继续查微信结果。
5. 用户支付和原路退款仍由服务端核算，并以微信验签或查单为准。不改成客服手填金额直接退。
6. 厨师可以限制接单、封禁、解除。健康证到期继续自动停新单，并在到期前发站内提醒。
7. 用户可以冻结。冻结后不能登录、报价、下单。列表里的手机号脱敏；查看完整号码要单独授权并写审计。
8. 四份协议按版本发布，小程序读取当前版本。
9. 后台可以按用户或厨师检索聊天，只读，不能代发。
10. 后台统计只读，不导出身份证、健康证、银行卡。

本轮明确不做：菜价券、团购、积分、次卡、用户余额、OCR、活体、真实保险、假保单、小区多边形、抢单匹配、微信订阅消息、会员和 B 端。
