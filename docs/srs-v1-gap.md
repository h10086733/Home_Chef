# V1.0 需求说明书与当前实现差异

核对日期：2026-10-23。来源是《厨临门平台软件开发需求规格说明书 V1.0》（CLD-SRS-2026-001，2026-10-23）。它把上门做饭、成品配送和平台担保交易写成一份可编码的规格，并声明功能、接口、数据和规则以该文档为准。

2026-10-23 用户明确指示按该文档开发，并说明产品尚未上线，历史订单和历史规则不需要迁移。正式库直接使用 V1.0。代码里仍保留「订单记下单时的规则快照」，那是为了上线以后改规则不影响进行中的订单，不是为了转换旧数据。

## 文档在讲什么

| 章节 | 内容 |
|---|---|
| 0–1 | 术语、P0/排除项、对旧需求的工程补齐、默认可配置参数 |
| 2 | 技术栈与鉴权、幂等、日志约定 |
| 3–4 | MySQL 表设计、REST 错误码、C/B/后台接口清单 |
| 5 | 用户小程序：登录、首页、找厨师、定制菜谱、下单支付、订单、IM、评价、入驻、订阅消息 |
| 6 | 厨师工作台：履约、菜品、价格、范围、证照、钱包提现、数据 |
| 7 | 后台：权限、参数、用户、审核、风控、内容、营销、订单、财务、IM、工单、统计、日志 |
| 8 | 按道计价、优惠券、状态机、取消退款阶梯、确认后 24 小时结算、提现、推荐排序 |
| 9–12 | 性能安全、微信/短信/百度地图、验收用例、里程碑；附录 D 为待确认项 |

明确排除：智能派单、多商户、视频直播、发票、积分兑换、多城市独立运营。

## 已按 V1.0 实现（2026-10-23）

规则参数集中在 `apps/api/src/policy.ts` 的 `SRS_DEFAULTS`，后台「规则」页发布时可调整。

| 事项 | 实现 |
|---|---|
| 平台佣金 | 默认 0%，基数为净额（实收−退款）；旧快照仍按服务费基数 |
| 结算 | 用户确认（或 48 小时自动确认）后 24 小时，无进行中售后、费用结清，worker 自动结算入余额 |
| 取消 | 预览接口展示档位和扣费；≥24h 全退，6–24h 扣基础服务费 30%，<6h 扣 50%，已到达 100%；接单前全退。扣款部分原路少退，并作为厨师补偿结算；提交时带预览金额，规则变化则拒绝 |
| 厨师取消 | 接单后取消须填原因，记违约处罚 |
| 预约与超时 | 提前至少 2 小时、最多 30 天；报价 30 分钟内支付；指定厨师 30 分钟未接单自动取消退款 |
| 提现 | 最低 100 元、每日 3 次（按北京时间）、同时只能一笔进行中、提交后不可撤销 |
| 证照 | 入驻须上传意外险凭证和到期日；健康证/意外险续期提交、审核员审批；健康证过期停单，审核通过后恢复；保险过期 60 天缓冲，到期前提醒，缓冲后不展示接单 |
| 账号 | 注册服务端校验同意协议（含微信首次登录）；密码错 5 次锁 30 分钟；注销 15 天冷静期，期间登录即撤销，到期匿名化 |
| 风控 | IM R001–R005（手机号含全角/中文数字、微信、QQ、支付宝/链接）拦截；R006–R007（私下交易、辱骂）打码；非后台接口响应出口手机号脱敏 |

保险说明：平台只审核厨师自行上传的保险凭证，不代投保、不生成保单，未接保险公司核验。

## 已经对齐或基本对齐

- 单城市试点（长沙），用户全额预付，平台记账后再给厨师。
- 新订单服务结束后 48 小时未确认则自动确认。
- 本期不做微信分账；提现由财务审核后线下打款。代码里是两人分权（一人审、另一人登记凭证），文档写成同一财务流程里的两步。
- 微信小程序用微信支付；网页/H5 没有独立收银台。
- 微信手机号可注册登录；号码加密，后台查看完整号码留审计。
- 厨师人工审核后才能接单。
- 订单内聊天后台只读，且要有开放工单。
- 金额以分为单位，支付和退款以服务端及微信结果为准。

## 只做了一部分

| V1.0 | 现在 |
|---|---|
| 微信一键 + 短信验证码 + 手机号密码 | 微信手机号登录、账号密码登录已接。没有短信验证码 |
| 首页定位、搜索、厨师卡片 | 有公开列表、菜系/价格/距离、收藏、地图选点。没有轮播、金刚区、活动位、优惠券专区 |
| 套餐与厨师自定价 | 厨师自建套餐，按套餐服务费报价。没有公共菜品库、按道阶梯、硬菜加价、清洁费、主食加份 |
| 现场加菜最多 2 道并二次支付 | 有改约、改菜单、采购预算补款。没有独立加菜单和 1.2 倍加价 |
| 评价 | 口味、服务、准时各 1–5 星和文字，可追评。没有配图，没有低分进人工审核 |
| 厨师钱包 | 余额、冻结、结算、线下提现、V1.0 提现限制、裁定后退款追偿。没有银行卡开户人与实名一致性校验，没有提现手续费。微信分账已出款不能自动追回 |
| 后台统计 | 有概览计数。没有报表导出、对账差异表、操作日志 365 天只增不改 |

## 文档要求、当前没有

- 成品配送、平台或第三方跑腿、配送单厨师可为空。
- 定制菜谱（多厨师收藏，下单时再收束到一位厨师）。
- 优惠券模板、领取锁定、门槛和核销；团购；积分流水。
- 身份证 OCR、活体、人脸比对。
- 微信/支付宝订阅消息，短信验证码和通知短信。
- 支付宝小程序支付。
- 全表 `city_code`、MySQL 全文加拼音搜索、对象存储签名 URL、腾讯云 IM。
- 计价引擎与文档第 11 章那组金额验收用例（200 元基础服务费、阶梯、硬菜、清洁费）。

技术栈不按说明书重写（Spring Boot/MySQL/Vue3 等），新功能继续落在现有 Node API、PostgreSQL、Taro 小程序和 React 后台。
