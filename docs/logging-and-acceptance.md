# 日志与功能验收（2026-09-17）

## 日志范围

API、微信接口、后台任务输出 JSON 单行日志，包含 UTC 时间、等级、事件名、请求编号、接口模板、状态码及耗时。已登录请求可带内部用户编号，资金处理带支付单或任务编号。接口响应头 x-request-id 和错误响应 error.requestId 用于反馈问题；数据库 AuditEvent.traceId 与请求编号关联。未经过 HTTP 的任务保留独立审计编号。

记录 http.completed、api.request.failed、http.framework_error、api.started/start_failed/stopping、wechat.request.completed/failed、payment.prepared/callback.accepted/reconcile_pending、transfer.callback.accepted、finance.reconcile_pending、worker.started/disabled/tick.completed/tick.failed/job.failed/connection.failed/queue.failed/start_failed。

callback.accepted 表示通知经过验证并已交由幂等状态处理，不表示新增了一笔资金。最终收款、退款、提现结果以数据库支付记录、不可变流水和审计记录为准；运行日志不能代替财务账本。

不记录请求正文、完整查询参数、Authorization、密码、微信 OpenID、密钥、签名、回调密文、图片、详细地址、实名姓名、聊天正文。错误记录保留类型、错误代码和调用位置，避免直接输出可能包含 SQL 参数的异常消息。字段白名单新增时必须检查是否涉及个人资料。

## 查看与保存

本地启动脚本输出到 .data/api.log、.data/worker.log；本轮测试日志为 .data/log-*.log 和 .data/business-test-api.log。这些文件只在本机，不进入版本管理；本地开发重启可能覆盖日志，不作为生产留存方案。

正式服务模板明确输出到 systemd journal：

```bash
journalctl -u home-chef-api -u home-chef-worker --since '1 hour ago' -o cat
journalctl -u home-chef-api -o cat | grep '请求编号'
journalctl -u home-chef-worker -p err --since today
```

JSON 中的 level 是应用等级，journal 默认按 stdout/stderr 接收；筛选应用错误应使用 JSON 字段（例如 jq 'select(.level == "error")'），不能只依赖 journal 优先级。第三条命令仅检查宿主服务级错误。

正式部署必须配置持久日志、磁盘限额与保留周期，并接入告警接收方。本次没有修改宿主机全局 journald 设置，也没有部署日志平台或发送外部告警。建议试运营先明确 14 天运行日志保留策略，财务审计独立保存，不随运行日志清理。日志与备份仅授权运营人员读取。
